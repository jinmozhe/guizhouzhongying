# 小程序已取消订单详情重构与取消事实字段扩展计划

## 1. 当前状态和结果

- 当前状态：已结束
- 结果：已完成；后端 `ConsumerTradeOrderRead` 向后兼容补充只读可选字段 `cancelled_at` 与 `cancel_reason` 并同步 OpenAPI 与 API 客户端，小程序按最新视觉稿重构已取消状态订单详情页（深灰蓝导航与票券头部、双层灰蓝叉号圆标、取消时间与取消原因、全宽“再来一单”按钮及灰蓝未支付金额卡），全栈轻量与治理门禁通过；重型自动化测试与微信真机动态验收未执行

## 2. 关联需求

- `BASE-COM-103`（订单列表、详情与状态展示）
- `BASE-COM-105`（订单状态事实与操作边界）
- 对应小程序需求：`MP-ORD-002`

## 3. 背景

订单表 `orders` 已有受数据库约束保障的 `cancelled_at`（取消时间）与 `cancel_reason`（取消原因）列，但此前 `ConsumerTradeOrderRead` 未投影这两个字段。本次按最新视觉稿重构小程序“已取消”状态订单详情页，需将这两项真实取消事实无破坏地暴露给消费者查询模型。

## 4. 目标

1. 在 `ConsumerTradeOrderRead` 新增可选只读字段 `cancelled_at` 与 `cancel_reason`（默认 `None`），对既有接口与消费方零冲突、零破坏；同步导出根 `openapi.json` 并重新生成 `@pinjie/api-client`。
2. 按最新视觉稿实现小程序已取消订单详情页（`CancelledOrderDetail`）：动态切换原生导航栏为深灰蓝配白字，顶部深灰蓝品牌区承载带两侧票券缺口的白色大卡（已取消标识、双层灰蓝叉号圆标、取消时间、取消原因、已取消状态胶囊）及全宽纯白“再来一单”按钮，下方呈现紧凑商家卡、灰蓝金额商品明细卡、带“未支付”标签的金额汇总卡及订单信息卡。

## 5. 非目标

- 不修改数据库表结构或新增 Alembic 迁移。
- 不修改管理端接口及其他订单状态页。
- 不执行未授权的重型测试（pytest、Vitest、小程序编译及真机动态验收）。
