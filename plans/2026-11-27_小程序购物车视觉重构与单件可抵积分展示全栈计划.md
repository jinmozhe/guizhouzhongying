# 小程序购物车视觉重构与单件可抵积分展示全栈计划

## 1. 当前状态和结果

- 当前状态：已结束
- 结束结果：已完成；后端 `ConsumerCartItemRead` 补充 `max_points_deduction` 字段、OpenAPI 导出与 API 客户端生成、小程序引入 NutUI `Del` 图标并按效果图重构购物车卡片、全选与底部双层汇总栏及文档均已完成，全栈轻量与仓库治理门禁通过；重型自动化测试与微信真机动态验收未执行

## 2. 关联需求

- `BASE-COM-101`：购物车与结算预览
- `BASE-LOCAL-004`：SKU 上限内积分与现金组合购买
- `BASE-MP-001`：C 端唯一形态为微信小程序
- `BASE-API-001`：根 `openapi.json` 是唯一 OpenAPI 契约
- `BASE-API-002`：API Client 由契约生成

## 3. 背景

小程序购物车页面需要按最新视觉效果图升级，展示商品卡片勾选、商品缩略图（无图回退深钴蓝圆角块）、规格标签、单行最高可抵扣积分标签、右上角删除按钮、右侧胶囊数量步进器，以及底部双层汇总栏（商品合计、积分最多可抵金额、全选切换、预计应付金额与去结算按钮）。当前后端 `GET /api/v1/cart-items` 返回的 `ConsumerCartItemRead` 缺少单件最高可抵扣积分字段，无法在购物车中真实计算每行与整批最高可抵积分。

## 4. 目标

1. 后端在 `ConsumerCartItemRead` 新增非破坏性只读字段 `max_points_deduction`（单件最高可抵扣积分，仅到店商品按 `min(sku.max_points_deduction, int(sku.price))` 计算，不可售或非到店商品为 `0`），同步导出根 `openapi.json` 并重新生成 `@pinjie/api-client`。
2. 小程序在公共 `Icon` 组件按需补充 NutUI 线性删除图标 `Del`，严格按效果图重构 `CartPage.tsx` 与 `cart.scss`（消费标准配色 tokens、整数分精确汇总、全选/取消全选切换、高权重覆盖微信原生按钮禁用态）。

## 5. 非目标

1. 不修改数据库表结构与迁移文件，不改变既有下单结算与服务端最终报价裁决逻辑。
2. 不改动管理端页面和永久冻结的 Web 端。
3. 不执行未获本次授权的重型验证（pytest、Vitest、build、微信编译与真机动态视觉验收）。

## 6. 现状分析

- 后端 `apps/backend/app/services/cart.py` 在 `CartService.list()` 中已一次性查询 `sku` 与 `product`，只需补充单件可抵扣积分投影，无额外查询或 N+1 风险。
- 小程序 `apps/miniapp/src/features/cart/CartPage.tsx` 当前为早期按钮式列表，缺少全选、汇总栏、积分抵扣预览与紧凑卡片排版。

## 7. 方案设计

1. **适用规则与落点核对**：
   - Backend 契约规则（`apps/backend/AGENTS.md`）：在 `ConsumerCartItemRead` 新增默认值为 `0` 的 `max_points_deduction: int = 0` 字段，保持向后兼容；完成后按固定顺序导出 `openapi.json` 并执行 `pnpm generate-api`。
   - 小程序配色与图标规范（`apps/miniapp/AGENTS.md`、`docs/design/miniapp/color-standard.md`）：全部复用 `tokens.scss` 语义变量，通过 `components/Icon` 按需引入 NutUI `Del` 图标，不引入自绘功能图标；原生 `<Button>` 禁用态统一用高权重 `[disabled]` 选择器覆盖微信基础库默认样式。
   - 金额精度：购物车前端汇总采用整数“分”计算，避免 JavaScript 浮点精度漂移，并保留“成交金额以结算报价为准”明确提示。
2. **Backend 与契约同步**：
   - 更新 `apps/backend/app/domains/cart/schemas.py` 与 `apps/backend/app/services/cart.py`。
   - 运行 `uv run python -m scripts.export_openapi` 与 `pnpm generate-api`。
3. **Miniapp 购物车页面重构**：
   - 更新 `apps/miniapp/src/components/Icon.tsx` 引入 `Del`。
   - 重构 `apps/miniapp/src/features/cart/CartPage.tsx` 与 `apps/miniapp/src/features/cart/cart.scss`，覆盖空态、加载态、失败重试、失效商品态、全选/取消全选、跨商家校验与单次 50 种上限拦截。

## 11. 风险与回滚

- **风险**：购物车底部预计应付金额未计入用户实时积分余额上限或会员阶梯价，需避免误导为最终成交价。
- **控制措施**：页面顶部保留“成交金额以结算报价为准”，底栏明确标注“预计应付”与“积分最多可抵”，最终金额与抵扣上限仍由服务端结算报价裁决。
- **回滚**：回退后端只读字段、重新导出契约并还原小程序购物车文件即可完整回滚。

## 15. 实施结果

1. **后端与契约同步**：
   - `apps/backend/app/domains/cart/schemas.py` 在 `ConsumerCartItemRead` 中新增只读字段 `max_points_deduction: int = 0`、`merchant_name: str | None = None` 与 `merchant_logo_url: str | None = None`；`apps/backend/app/services/cart.py` 在 `CartService.list()` 中按到店商品 `min(sku.max_points_deduction, int(price))` 计算单件最高可抵扣积分并批量回填商家名称与 LOGO，同时在 `add()` 与 `update(selected=True)` 的用户锁事务内原子取消其他商家的已选商品，保障同一时刻只结算单一商家。

2. **小程序购物车视觉与交互重构**：
