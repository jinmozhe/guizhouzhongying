## 3. 背景

当前商家档案仅支持上传单张 `logo_asset_id` 和编写受限 HTML 文本介绍，缺少专门展示线下门店环境、门头实景、资质证书等图文凭证的相册能力。消费者在小程序进入商家详情页时，难以直观确认门店实景与资质，运营人员也不便在后台集中管理多张商家图片。

平台此前已在商品领域建立“统一资产表 + 有序关联表 + Pillow 完整解码核验 + 资产删除引用拦截”的成熟机制，且小程序已具备受控图片组件与全屏预览工具，具备低风险复用与全栈落地的良好基础。

## 4. 目标

1. 后端建立 `merchant_album_images` 独立有序关联表，复用 `assets` 统一资产体系，实现商家相册的原子保存、顺序维护、可信尺寸/静态图校验与资产删除引用保护。
2. 公开与管理接口拆分列表与详情投影：列表接口保持轻量（管理端列表补充相册数量），仅详情接口返回完整有序相册数据；更新契约兼容未携带字段场景，杜绝缺字段静默清空。
3. 管理端在“新增/编辑商家”弹窗内通过加宽布局与双 Tab（基础资料 / 商家相册）实现多图批量上传队列、从素材库多选、任意位置排序、单张与批量移除确认，并与商家基础资料在同一次保存中提交。
4. 小程序在商家详情页的商家信息卡片下方、商家商品上方，按 3 列缩略图网格展示商家相册并支持微信原生全屏左右滑动预览；无图时自动隐藏相册区块，全面遵循[小程序标准配色方案](../docs/design/miniapp/color-standard.md)。
5. 保持既有权限模型、并发锁序、乐观版本控制（`revision`）、审计日志与契约生成链路一致。

## 5. 非目标

- 不支持相册分组分类、自定义标签或单张图片标题说明（统一作为有序图片集合管理）。
- 不开放 GIF 动图、SVG 矢量图、视频、外部任意图片链接或在线修图裁切能力。
- 不开放商家在小程序工作台自行上传或编辑相册（本期仅限具备 `merchants:update` 权限的后台运营人员维护）。
- 不在小程序首页“品牌商家”、分类页“本类商家”、独立“商家列表”和商品详情页“商家卡片”中展示相册图片。
- 不新增第三方上传、拖拽或图片处理依赖，不修改或启动永久冻结的 `apps/web`，不监听 3000 端口。
- 不在未获明确授权时自动执行本机/测试/生产数据库迁移、pytest、Vitest、production build、Playwright、微信开发者工具动态验收或 Git 提交推送。

## 7. 方案设计

### 7.1 数据模型与迁移

在 `apps/backend/app/db/models/local_commerce.py` 新增 `MerchantAlbumImage(Base)`，表名 `merchant_album_images`（参考 `ProductImage` / `ProductDetailImage` 关联表范式，保留联合业务主键，不人为增设 UUID 列）：

| 列名 | 类型与约束 | 说明 |
| --- | --- | --- |
| `merchant_id` | `UUID`，`ForeignKey("merchants.id", ondelete="RESTRICT")`，联合主键 | 所属商家 |
| `asset_id` | `UUID`，`ForeignKey("assets.id", ondelete="RESTRICT")`，联合主键 | 引用图片资产 |
| `position` | `Integer`，`NOT NULL`，`CheckConstraint("position >= 0")` | 相册内连续展示序号（从 0 起） |

约束与索引：

- `UniqueConstraint("merchant_id", "position", name="uq_merchant_album_image_position")`：保证同一商家相册内序号唯一。
- `CheckConstraint("position >= 0", name="ck_merchant_album_image_position")`：禁止负序号。
- `Index("ix_merchant_album_images_asset", "asset_id")`：支撑资产删除引用检查与外键保护查询。
- 关联表与全列补充准确中文 comment，并在 `apps/backend/app/db/models/__init__.py` 完成导出，确保纳入 Alembic metadata。

Alembic 迁移 `20261125_01_merchant_album_images.py` 仅创建新表、约束和索引，不改动已有商家行数据；已有商家默认相册为空。`downgrade()` 删除该表，仅在确认无保留价值的新相册数据且获授权后使用。

### 7.2 图片预算与可信资产校验

基于用户确认结果，商家相册复用 `UploadScene.PRODUCT` 统一资产通道，前端预检与后端权威校验执行同一预算标准：

| 校验项 | 标准 | 说明 |
| --- | --- | --- |
| 数量上限 | 0 至 20 张 | 同一商家相册内 `asset_id` 不可重复；允许跨商家或与 LOGO、商品复用同一资产 |
| 允许格式 | JPG、JPEG、PNG、WebP | 拒绝 GIF 动图、SVG 及非图片文件 |
| 单图体积 | 最大 5 MiB（5,242,880 字节） | 兼容手机直拍门店实景与证书原图，超限明确拒绝，不静默压缩 |
| 整组体积 | 最大 50 MiB（52,428,800 字节） | 按相册内全部资产 `file_size` 求和校验 |
| 解码与静图核验 | `width > 0`、`height > 0`、`frame_count == 1` | 复用 `UploadScene.PRODUCT` 阶段 Pillow 有界完整解码结果，拒绝动态 WebP 及未核验尺寸的资产 |
| 上传主体与场景 | `uploader_type IN ('admin', 'system')` 且 `scene == 'product'` | 禁止引用普通用户头像等非管理端公开素材 |

历史未回填尺寸的资产不能新绑定进商家相册，后端返回明确错误提示，前端素材选择器同步标注不可选原因。

### 7.3 并发控制、事务与资产删除保护

1. **统一加锁顺序**：在 `LocalActorsService._save` 中，合并当前请求的 `logo_asset_id`（如有）与本次提交的 `album_image_asset_ids`，去重后按 `Asset.id` 升序调用一次性 `SELECT ... FOR UPDATE` 锁定所有涉及资产，与 `AssetService._delete_many` 的升序加锁顺序保持一致，防止商家保存与资产删除交叉死锁。
2. **原子替换相册关联**：保存商家主体信息、同步核销用户绑定、替换 `merchant_album_images`（先删除旧关联再 `flush`，随后按列表顺序以 `position = 0, 1, ..., n-1` 批量写入新关联）以及审计记录全部在同一个事务内完成；失败整体回滚。
3. **版本并发保护**：更新商家相册同步校验并递增 `Merchant.revision`，防止多人同时编辑互相覆盖。
4. **资产删除保护**：
   - 在 `CommerceAccessRepository` 新增 `asset_is_merchant_album_image(asset_id)` 检查（与现有 `Merchant.logo_asset_id` 检查共同覆盖商家全部图片引用）。
   - 在 `AssetService._delete_many` 中拦截被商家相册引用的资产删除请求，返回 HTTP 409 与清晰业务提示“商家图片正在被使用，无法删除”；数据库 `ON DELETE RESTRICT` 继续作为底层兜底。
   - 从商家相册移除图片仅解除关联，不物理删除原资产文件；已上传但未保存或取消编辑的资产留由既有资产库管理。

### 7.4 API 契约设计（零破坏性变更）

在 `apps/backend/app/services/local_commerce_schemas.py` 与 `apps/backend/app/api/local_commerce_router.py` 调整如下：

1. **新增相册输出 Schema**：
   - `PublicMerchantAlbumImageRead`：仅公开 `url: str`、`width: int`、`height: int`（不泄露 `asset_id`、`uploader_id`、`file_hash`、`file_key` 等内部字段）。
   - `MerchantAlbumImageRead`（管理端专用）：包含 `asset_id: UUID`、`url: str`、`original_name: str`、`file_size: int`、`width: int | None`、`height: int | None`、`frame_count: int | None`。
2. **拆分列表与详情投影**：
   - `PublicMerchantRead` 保持不变，供 `GET /api/v1/merchants` 与 `GET /api/v1/merchants/browse` 使用，避免列表膨胀与 N+1。
   - 新增 `PublicMerchantDetailRead(PublicMerchantRead)`，增加 `album_images: list[PublicMerchantAlbumImageRead] = Field(default_factory=list)`，供 `GET /api/v1/merchants/{merchant_id}` 返回。
   - `MerchantRead` 增加 `album_image_count: int = Field(default=0, ge=0)`，管理端商家列表一次聚合查询各商家相册数，消除 N+1。
   - 新增 `MerchantDetailRead(MerchantRead)`，增加 `album_images: list[MerchantAlbumImageRead] = Field(default_factory=list)`。
3. **新增管理端详情查询端点**：
   - `GET /api/v1/admin/merchants/{merchant_id}`，声明 `PermissionCode.MERCHANTS_READ`，返回 `ResponseModel[MerchantDetailRead]`。
4. **商家创建与更新入参**：
   - `MerchantInput` 新增 `album_image_asset_ids: list[UUID] = Field(default_factory=list, max_length=20)`（带唯一性校验）。
   - `MerchantUpdate` 覆写 `album_image_asset_ids: list[UUID] | None = Field(default=None, max_length=20)`，并通过字段校验明确禁止显式传入 `null`（清空请传空数组 `[]`）；服务端依据 `"album_image_asset_ids" in data.model_fields_set` 判断是否更新相册。未携带该字段时不触碰原相册，既杜绝缺字段静默清空，也避免对现有 `PUT` 契约引入 Breaking Change。
   - `POST /api/v1/admin/merchants` 与 `PUT /api/v1/admin/merchants/{merchant_id}` 返回 `ResponseModel[MerchantDetailRead]`（为 `MerchantRead` 超集，兼容既有消费方）。

### 7.5 管理端交互设计

1. **列表页 (`MerchantsPage.tsx`)**：
   - 在商家列表新增“相册”列，展示已绑定张数（如 `0 张` / `6 张`），沿用表头与单元格 `white-space: nowrap`、垂直居中及 `scroll={{ x: "max-content" }}`。
   - 保留现有筛选、分页、批量启停与编辑操作列结构。
2. **新增/编辑弹窗 (`Editor`)**：
   - 将 `EditorModal` 宽度调整为 `880`，内部使用 Ant Design `Tabs` 分为两个标签页：`基础资料` 与 `商家相册 (N)`。
   - 编辑商家时调用 `GET /api/v1/admin/merchants/{id}` 获取最新详情与相册列表（同时获取最新 `revision`），覆盖加载中、加载失败与重试状态；加载未完成前不渲染表单或允许误提交。
   - 保持 `基础资料` 表单项与 `商家相册` 草稿在切换 Tab 时均保留状态；提交时先校验表单，再随完整 `album_image_asset_ids` 一次性调用创建或更新接口。
   - 当相册处于上传队列运行中或存在未处理失败项时，将 `EditorModal` 的 `blocked` 设为 `true`，禁止点击保存或误关闭弹窗，并给出明确提示。
3. **商家相册组件 (`MerchantAlbumGallery.tsx` 与 `merchant-album-policy.ts`)**：
   - **上传队列**：支持一次多选多个图片文件，串行受控调用 `adminApi.uploadAsset(file, "product")`（走唯一 `http.ts` 管道，含 Cookie、CSRF 与错误解包）；保留选择顺序，单张失败原位展示错误原因并支持重试或移除，组件卸载后停止状态回写。
   - **从素材库选择**：点击“从素材库选择”打开受控多选弹窗，分页搜索 `scene="product"` 的管理端静态图片，实时按数量与整组 50 MiB 预算限制可选状态并展示不可选原因；无 `assets:read` 权限时隐藏素材库入口并提示仍可本地上传且已绑定图片会保留。
   - **排序与预览**：以紧凑列表或缩略图条目展示序号、64×64 缩略图（支持 `Image.PreviewGroup` 大图预览）、文件名、分辨率与文件大小；提供上移、下移、置顶、置底按钮。
   - **移除二次确认**：单张移除与勾选批量移除均通过 `StandardConfirmModal` 二次确认，明确文案“移除选中的 N 张图片，保存商家后解除关联；已上传文件仍保留在资产库。取消将保留当前草稿。”

### 7.6 小程序商家详情页展示设计

1. **页面结构 (`apps/miniapp/src/features/local-commerce/Merchant.tsx` 与 `merchant.scss`)**：
   - 保持顶部商家基础信息卡片（LOGO、名称、停用提示、地址、营业时间、公开电话、受限 HTML 介绍）与下方“商家商品”分页列表。
   - 在两者之间新增“商家相册”卡片（`.surface`）：
     - 若 `row.album_images.length === 0`，完全隐藏该卡片，不占页面空间。
     - 若有图片，顶部显示标题“商家相册”与次要文字计数（如 `共 6 张`），下方采用 3 列等宽正方形缩略图网格（`display: grid; grid-template-columns: repeat(3, minmax(0, 1fr))`）。
2. **图片渲染与全屏预览**：
   - 每张缩略图复用 `ProductImage` 组件（`mode='aspectFill'`），自动获得受控资源域名校验（`assetUrl`）、懒加载及加载失败原位重试能力。
   - 点击任意一张缩略图调用既有 `previewImages(urls, item.url)`（底层 `Taro.previewImage`），支持全屏高清查看原图、双指缩放与左右滑动切换整组相册图片（查看清晰证书文字与门店细节）。
3. **视觉与配色约束**：
   - 卡片面使用白色内容面、标题使用墨蓝正文色、数量说明使用次要文字色、图片容器使用页面底色占位和分隔色细边框，所有颜色均消费 `apps/miniapp/src/styles/` 语义 tokens，不散落硬编码色值，不对真实商家业务图片叠加滤色。

## 11. 风险与回滚

- **单图与整组预算边界**：5 MiB 单图与 50 MiB 整组兼顾手机直拍清晰度与加载体验；若真实运营照片普遍偏大或弱网加载缓慢，后续可通过新计划调整预算或补充缩略图策略，不静默降质或截断。
- **历史无尺寸资产不可绑定**：早期未回填 `width/height/frame_count` 的资产会被校验拦截，需先通过既有资产尺寸回填工具补齐或重新上传，避免小程序端元数据缺失。
- **并发编辑与资产删除竞争**：统一按 `Asset.id` 升序行锁与 `Merchant.revision` 乐观锁避免死锁与覆盖；真实并发行为仍需授权执行 PostgreSQL 集成测试验证。
- **上传成功但未保存商家**：已上传图片保留在资产库，不自动反向删除，避免误删跨实体复用素材；由管理员在资产库按需清理。
- **数据库未升级时的运行差异**：若仅完成本地源码修改而未升级本机开发库，运行时访问 `merchant_album_images` 会报错；须在用户授权升级本机开发库后才可用于本地联调。
- **回滚边界**：代码层可通过回退提交恢复；数据库新增表结构未写入生产数据前可直接降级删除表，写入业务数据后应采用前向修复或基于迁移前备份恢复，禁止无备份丢弃相册数据。
