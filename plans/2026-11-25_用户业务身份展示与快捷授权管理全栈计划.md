# 用户业务身份展示与快捷授权管理全栈计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；后端业务身份聚合与筛选、单条物业详情接口、`/users/me/business-roles` 摘要增强、OpenAPI 与 API Client 同步、管理端用户管理业务身份展示与条件化快捷授权弹窗、小程序“我的”页面业务身份标签展示及配套文档均已完成，全栈轻量门禁与模块边界检查通过；重型测试与动态视觉验收未执行

## 2. 关联需求

- `BASE-LOCAL-001`：会员基础身份与商家、物业附加身份
- `BASE-LOCAL-002`：独立商家档案与可信手机号关联
- `BASE-LOCAL-003`：物业向注册用户增加积分
- `BASE-ADMIN-002`：管理页面覆盖主要操作状态
- `BASE-ADMIN-003`：运营能力与服务端权限一致
- `BASE-API-001`：根 `openapi.json` 是唯一 OpenAPI 契约
- `BASE-API-002`：API Client 由契约生成
- `BASE-MP-002`：小程序按专项接入 Backend 与 Admin

## 3. 背景

当前系统通过 `merchants` 与 `property_operators` 两张独立业务表按可信手机号关联 C 端用户，支持会员同时兼任商家核销员与物业发分员，但存在两处展示与操作缺口：

1. 管理端“用户管理”页仅展示 `users` 表基础信息，无法直接查看用户关联的商家/物业身份，也无法按业务身份筛选或快速进入已有授权的编辑维护。
2. 小程序 `GET /api/v1/users/me/business-roles` 仅返回 `merchant_id` 与 `property_operator_id`，未返回商家名称、物业名称和启用状态，“我的”页面仅在服务九宫格按 ID 显隐入口，顶部用户身份区未直观体现当前身份信息。

## 4. 目标

1. 后端扩展 `AdminUserRead` 与 `LocalRolesRead`，补充结构化商家/物业业务身份摘要（`id`、`name`、`is_active`），新增用户列表 `business_role` 筛选参数及单条物业授权查询端点 `GET /api/v1/admin/property-operators/{operator_id}`。
2. 同步导出根 `openapi.json` 并重新生成 `@pinjie/api-client`。
3. 管理端“用户管理”页新增“业务身份”列与业务身份筛选；仅当用户存在商家或物业身份且当前管理员拥有对应查看与更新权限时，显示“管理商家授权”或“管理物业授权”按钮，拉起对应编辑弹窗完成换号或启停（复用既有接口、权限与乐观锁 `revision`）。用户无商家或物业身份时不显示相关操作按钮，不提供“设为物业”及“以此手机号新建商家”入口。
4. 小程序“我的”页面消费增强后的 `/users/me/business-roles` 返回信息，在顶部个人卡片清晰展示当前会员及关联商家/物业身份名称与状态，操作入口继续仅在有效启用时开放。

## 5. 非目标

1. 不修改数据库表结构，不新增 Alembic 迁移。
2. 不在“用户管理”页提供“设为物业”、“以此手机号新建商家”或直接勾改用户角色的写入接口。
3. 不改变小程序商家/物业操作入口的权限裁决边界与核销/发分业务规则。
4. 不执行未授权的重型验证（pytest、Vitest、production build、Playwright、真机验收）及 Git 远端/发布/部署动作。

## 6. 现状分析

1. 后端 `GET /api/v1/admin/users` 在 `UserRepository.list_users` 查询 `User`，由 `AdminManagementService._user_read` 组装 `AdminUserRead`，未查询 `merchants` 与 `property_operators`。
2. 后端已有 `GET /api/v1/admin/merchants/{merchant_id}`，但缺少按 ID 获取单条物业授权的 `GET /api/v1/admin/property-operators/{operator_id}`。
3. 后端 `LocalActorsService.roles` 仅返回 `member`、`merchant_id`、`property_operator_id`，停用状态的关联记录未向用户展示名称与状态提示。
4. 管理端 `features/local-commerce` 尚无公开入口 `index.ts`，`MerchantsPage.tsx` 与 `PropertyOperatorsPage.tsx` 各自内聚编辑弹窗。
5. 小程序 `AccountPage.tsx` 已拉取 `/users/me/business-roles`，但未将角色摘要透传给顶部 `AccountSummary` / `SignedInSummary` 展示。

### 7.2 Backend 设计

1. 新增轻量业务身份摘要模型：
   - `apps/backend/app/domains/admin/schemas.py` 新增 `UserBusinessRoleSummary(id, name, is_active)`，并在 `AdminUserRead` 增加 `merchant_role` 与 `property_role`（默认 `None`）。
   - `apps/backend/app/services/local_commerce_schemas.py` 新增 `BusinessRoleSummaryRead(id, name, is_active)`，并在 `LocalRolesRead` 增加 `merchant_role` 与 `property_role`（默认 `None`），保留原有 `member`、`merchant_id`、`property_operator_id` 兼容字段。
2. 批量查询与筛选：
   - `UserRepository.list_users` 新增 `business_role: Literal["all", "member_only", "merchant", "property"] = "all"`，使用 `EXISTS` 子查询按 `merchants.user_id` 与 `property_operators.user_id` 精确过滤。
   - `LocalActorsRepository` 新增 `merchants_by_users(user_ids)` 与 `operators_by_users(user_ids)`，按当前页用户集合一次性查询映射，杜绝 N+1。
   - `AdminManagementService.list_users` 与 `restore_user` 组装 `merchant_role` 与 `property_role`。
3. 物业单条查询端点：
   - `LocalActorsService.admin_operator(operator_id)` 按 ID 读取 `PropertyOperator`，不存在抛 404。
   - `local_commerce_router.py` 新增 `GET /api/v1/admin/property-operators/{operator_id}`，声明 `PermissionCode.PROPERTY_OPERATORS_READ`。
4. 小程序业务身份摘要：
   - `LocalActorsService.roles(user_id)` 在 `user.phone_bound` 且业务表 `phone_e164 == user.phone_e164` 时返回 `merchant_role` / `property_role`（包含 `id`、`name`、`is_active`）；`merchant_id` 与 `property_operator_id` 继续仅在 `is_active` 为真时非空，确保停用授权实时失去入口与操作权。

### 7.3 Admin 设计

1. 抽出并经 `apps/admin/src/features/local-commerce/index.ts` 公开导出：
   - `MerchantEditModal`：按 `merchantId` 调用 `GET /api/v1/admin/merchants/{id}` 加载详情，复用完整编辑表单（含 `revision` 乐观锁），提交 `PUT /api/v1/admin/merchants/{id}`。
   - `PropertyOperatorEditModal`：按 `operatorId` 调用 `GET /api/v1/admin/property-operators/{id}` 加载单条授权，复用编辑表单（含 `revision` 乐观锁），提交 `PUT /api/v1/admin/property-operators/{id}`。
2. `UsersPage.tsx` 改造：
   - 工具栏新增“业务身份”筛选（全部身份 / 仅普通会员 / 商家 / 物业），切换时重置分页并清空选择。
   - 表格新增“业务身份”列：无附加身份显示“普通会员”；有商家或物业时以标签展示角色名称与启停状态（长名称省略并用 Tooltip 提示完整名称）。
   - 操作列按需展示按钮：仅当用户存在 `merchant_role` 且管理员拥有 `merchants:read` 与 `merchants:update` 时显示“管理商家授权”；仅当用户存在 `property_role` 且管理员拥有 `property-operators:read` 与 `property-operators:update` 时显示“管理物业授权”。用户无商家或物业身份时不显示这两个按钮，不新增“设为物业”或“以此手机号新建商家”按钮。
   - 授权编辑保存后同时刷新 `admin-users` 与对应商家/物业缓存。

### 7.4 Miniapp 设计

1. `AccountPage.tsx` 将 `/users/me/business-roles` 查询结果状态传给 `SignedInSummary`（再传给 `AccountSummary`）。
2. `AccountSummary.tsx` 在已绑手机且角色查询成功后，于顶部用户信息区展示身份标签：
   - `member` 为真时展示“普通会员”。
   - 存在 `merchant_role` 时展示“商家 · 门店名”（若 `is_active` 为假，补充“已停用”并切禁用样式）。
   - 存在 `property_role` 时展示“物业 · 物业名”（若 `is_active` 为假，补充“已停用”并切禁用样式）。
   - 查询加载中或失败时不伪造身份标签；“我的服务”中核销/应收/发分入口继续严格依赖 `merchant_id` 与 `property_operator_id`（仅启用态展示）。
3. 样式仅使用 `apps/miniapp/src/styles/tokens.scss` 语义 tokens，不写入硬编码色值。

## 11. 风险与回滚

- **风险 1**：管理端跨 Feature 引用编辑弹窗若穿透内部文件会触发边界门禁失败。缓解：在 `features/local-commerce/index.ts` 暴露稳定公开组件，并执行 `pnpm check:boundaries` 校验。
- **风险 2**：停用态商家/物业若在小程序误开放操作入口会导致越权提示。缓解：小程序核销/应收/发分入口继续严格判断 `merchant_id` / `property_operator_id`（仅启用时后端返回非空），`merchant_role` / `property_role` 仅用于身份名称和状态展示。
- **风险 3**：用户列表筛选与批量聚合引入 SQL 性能退化。缓解：`merchants.user_id` 与 `property_operators.user_id` 已有唯一索引，`EXISTS` 过滤和 `IN (user_ids)` 批量查均走索引。
- **回滚**：无数据库迁移，全部代码与生成契约可通过普通代码回退恢复。
