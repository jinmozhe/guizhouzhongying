# 小程序商品商家联系计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成

## 关联需求与授权

- `BASE-LOCAL-002`、`BASE-LOCAL-006`，小程序细项 `MP-LOCAL-007`。
- 用户要求重新设计商品详情内的商家卡，有营业时间时展示，有公开电话时提供带图标的拨号入口。

## 范围与设计

- 小程序商品详情商家卡采用左图右文。右侧突出店名，次行展示地址和已填写的营业时间，右上保留详情入口。缺图沿用无文字浅灰占位。
- 卡片底部按公开电话展示独立的“联系商家”按钮。点击通过微信原生拨号，号码取自现有公开商家响应。商家查询保留加载和重试状态。

| 范围 | 是否涉及 | 工作内容与前置依赖 | 验证方式 |
| --- | --- | --- | --- |
| Miniapp | 涉及 | 商家卡、局部样式和 NutUI 电话图标。依赖既有公开商家响应和 Taro 拨号能力 | typecheck、lint、样式检查和交互分支复读 |
| Backend、Admin、API Client | 不涉及 | 使用既有商家公开字段 | 核对公开契约和工作区差异 |
| Web、Database、Deployment | 不涉及 | 小程序内的展示和交互 | 核对工作区差异 |
| Documentation | 涉及 | 同步需求、UI 规范、计划与变更记录 | 文档和 Markdown 检查 |

## 实施、风险与回滚

1. 按小程序 UI 规范在商家卡旁维护局部样式，复用现有色值、间距、缩略图占位和公共图标入口。复读长文换行、点击区和有无字段的布局分支。
2. 根据既有 `public_phone` 接入 Taro 拨号，与详情跳转使用独立控件。复读空白电话、触发拨号和失败提示分支。
3. 同步产品需求和交付记录。原生拨号效果通过微信真机验收。需回滚时可独立还原本计划的源码和文档差异。

## 实施结果与验证

- 按用户后续反馈，首行展示 LOGO、单行省略的店名和地址，次行左侧依次展示营业时间和拨号按钮，右侧展示详情链接。LOGO、店名及详情链接进入商家页。营业时间和公开电话去除首尾空白后有值才展示，无营业时间时拨号按钮左对齐。拨号未完成时提示可重试。
- 小程序 typecheck、lint、模块边界和 Sass 编译检查通过。源码复读确认了条件显示和点击处理。
- 微信开发者工具预览、生产构建、Vitest 和真机拨号未执行。实际页面排版和拨号弹窗待微信端确认。
