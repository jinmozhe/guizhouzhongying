# 小程序结算无感提交与内存防重优化计划

## 1. 当前状态和结果

- 当前状态：已结束
- 结果：已完成；小程序结算会话已改为纯内存管理并清理旧版缓存键，确认订单页移除独立恢复拦截页与二次确认弹窗，改为点击直接禁用按钮原地等待、明确拒绝原地展示原因、超时自动静默查询原请求防重，移除“我的”服务区“继续结算”入口并同步文档，Miniapp 与文档治理轻量门禁通过；重型自动化测试与微信真机动态验收未执行

## 2. 关联需求

- `BASE-COM-101`（购物车与结算流程）
- `BASE-COM-102`（下单幂等与报价指纹一致性）
- `BASE-COM-105`（订单结果查询与防重下单）
- 对应小程序需求：`MP-CHK-002`、`MP-CHK-003`、`MP-UX-002`

## 3. 背景

此前小程序结算页将草稿持久化到 `Taro.setStorageSync`，并在服务端返回非 `400 / 409 / 422` 异常（含配置未就绪 `503` 或网络抖动）后，将用户永久锁定在独立的“请先确认原下单结果”拦截页中，且在“我的”服务区保留“继续结算”入口。这种把后端幂等技术细节直接裸露为阻塞页的做法对 C 端用户干扰较重。

## 4. 目标

1. 保持后端 `request_id` 幂等锁、`quote_fingerprint` 校验与 `GET /api/v1/orders/by-request/{request_id}` 严谨性不变。
2. 小程序结算上下文改为纯内存会话管理，不再读写 `Taro.setStorageSync` 持久草稿，并清理可能残留的旧本地缓存键。
3. 结算页点击“确认创建订单”后直接发起提交（移除二次确认弹窗），按钮立即置为禁用加载态并停留在结算页等待异步结果；建单成功后直接跳转订单详情/支付页；失败时原地提示具体原因，彻底移除独立的“请先确认原下单结果”恢复页。
4. 遇到网络超时、断网或未知 `5xx` 时，前端自动静默查询一次 `GET /orders/by-request/{request_id}`：若已建单则无感直接跳转，未建单或查单失败则原地解锁按钮并提示原因，同时在当前页面内存中继续复用原 `request_id` 防重。
5. 从“我的”服务列表移除“继续结算”入口，并同步更新相关运维与需求文档。

## 5. 非目标

- 不修改 Backend 订单创建、幂等校验、查单接口及数据库模型。
- 不修改 Admin 管理端和 OpenAPI 契约。
- 不执行未授权的重型测试（Vitest、pytest、production build、微信真机动态验收）。

## 7. 方案设计

1. **纯内存结算会话（`apps/miniapp/src/features/checkout/draft.ts`）**：以模块级内存变量 `currentSession` 替代 `Taro.setStorageSync`，提供 `loadCheckoutSession`、`saveCheckoutSession`、`clearCheckoutSession`、`clearLegacyDraft`、`requestCheckoutIntent` 与 `startCheckout`；进入结算时自动清理历史本地缓存键，离开页面卸载时清空内存会话。
2. **原地无感提交状态机（`apps/miniapp/src/features/checkout-page/CheckoutPage.tsx`）**：
   - 点击“确认创建订单”直接提交，立即加锁禁用按钮与积分输入，按钮显示 `正在创建订单…`。
   - 建单成功后清理关联购物车条目、刷新缓存、释放内存会话并 `Taro.redirectTo` 跳转至订单详情/支付页。
   - `409 CHECKOUT_STALE_QUOTE` 原地自动刷新报价；其他确定性拒绝（`400 / 403 / 404 / 409 / 422` 及明确 `503 SERVICE_UNAVAILABLE`）原地解锁并展示中文失败原因与追踪编号。
   - 网络异常或未知 `5xx` 在解锁前自动静默请求一次 `GET /orders/by-request/{request_id}`（5 秒超时）：若已存在订单则直接跳转；若返回 `404` 或查单失败则解锁按钮并在原地给出原因，且在用户未改商品/积分前继续复用同一 `request_id`；用户修改积分后再提交时自动换新 `request_id`。
3. **入口清理（`apps/miniapp/src/features/account/entries.ts`）**：移除服务区“继续结算”入口。

## 15. 实施结果

1. **纯内存结算会话（`apps/miniapp/src/features/checkout/draft.ts`、`index.ts`）**：移除 `Taro.setStorageSync` / `getStorageSync` 持久草稿读写和 `submitted` 拦截跳转，改为模块级内存会话管理，并在进入结算时自动清理历史残留的旧版缓存键，离开结算页或建单完成后立即释放。
2. **结算页原地无感提交状态机（`apps/miniapp/src/features/checkout-page/CheckoutPage.tsx`、`checkout.scss`）**：移除独立“请先确认原下单结果”卡片分支、手动恢复按钮、`.checkout-recover-actions` 样式及提交前二次确认弹窗，底部按钮文案调整为“确认提交订单”；点击后立即加锁禁用按钮与积分输入并展示 `正在提交订单…`；成功后静默清理购物车条目并 `redirectTo` 跳转至订单详情/支付页；报价变化（`CHECKOUT_STALE_QUOTE`）原地自动刷新最新金额并弹出微信原生标准提示框；其他明确拒绝统一通过微信原生标准弹窗（`Taro.showModal` + `modalColors`）展示具体原因与追踪编号，不再在页面顶部渲染错误卡片挤压布局；网络超时或未知 `5xx` 在解锁前自动静默请求一次 `GET /orders/by-request/{request_id}`，已建单直接跳转，未建单或查单失败弹窗提示原因并在未改积分前继续复用同一 `request_id` 防止重复下单，改积分后自动换新 `request_id`。
3. **入口与文档同步**：移除 `apps/miniapp/src/features/account/entries.ts` 中的“继续结算”服务入口，同步更新 `docs/operations/miniapp-identity-and-content.md`、`docs/MINIAPP_PRD.md`、`docs/architecture/miniapp-ui-standard.md`、`plans/INDEX.md` 与 `CHANGELOG.md`。
4. **轻量门禁验证**：`@pinjie/miniapp` typecheck 与 lint、`pnpm check:boundaries`、`pnpm check:text`、`pnpm lint:md`、`pnpm check:documents`、`pnpm check:workspace` 与 `git diff --check` 全部通过；未产生新增本地临时缓存。
