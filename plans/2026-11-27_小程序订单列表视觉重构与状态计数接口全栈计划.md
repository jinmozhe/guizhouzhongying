# 小程序订单列表视觉重构与状态计数接口全栈计划

## 1. 当前状态和结果

- 当前状态：已结束
- 结果：已完成；后端新增无冲突只读聚合接口 `GET /api/v1/orders/summary`、导出根 `openapi.json` 并重新生成 `@pinjie/api-client`，小程序按最新视觉稿重构订单列表页（五态胶囊筛选与金柑橙全量角标、商家头部与跳转、商品行、待付款倒计时提示、待核销一单一码提示、时间与积分抵扣标签、分状态胶囊操作按钮及触底连续加载），全栈轻量与治理门禁通过；重型自动化测试与微信真机动态验收未执行

## 2. 关联需求

- `BASE-COM-103`（订单列表、详情与状态展示）
- `BASE-COM-105`（订单查询与本人订单操作边界）
- `BASE-LOCAL-005`（到店一单一码核销与 7 天未用自动退款提示）
- 对应小程序需求：`MP-ORD-001`、`MP-ORD-002`、`MP-LOCAL-005`

## 3. 背景

微信小程序“我的订单”列表页（`subpackages/trade/orders/index`）目前仍为早期基础列表卡片与“上一页/下一页”按钮分页，无法完整承载新视觉稿中的顶部状态胶囊、待付款/待核销真实全量角标、商家 LOGO 头部、待付款实时倒计时提示、待核销一单一码说明、实付/应付及积分抵扣标签、分状态操作按钮（取消订单、微信付款、导航、查看核销码、再来一单）及触底连续加载。

## 4. 目标

1. 保持既有 `GET /api/v1/orders`、`GET /api/v1/orders/{order_id}` 及管理端 `/api/v1/admin/orders` 零变更、零冲突，新增本人只读汇总接口 `GET /api/v1/orders/summary` 返回真实全量 `pending_payment` 与 `awaiting_delivery` 计数，严禁用前端当前页条目伪造角标。
2. 同步导出根 `openapi.json` 并重新生成 `packages/api-client`。
3. 按最新视觉稿重构 `apps/miniapp/src/features/orders/OrdersPage.tsx` 的订单列表页及专属样式，覆盖全部、待付款、待核销、已完成、已取消五个筛选胶囊与真实全量角标、商家头部直达商家详情、商品行与规格标签、待付款倒计时提示条（仅提示，不前端自动取消）、待核销提示条、下单/核销时间与积分抵扣标签、实付/应付汇总、分状态胶囊操作按钮（取消订单、微信付款、导航、查看核销码、再来一单）以及触底连续加载与“没有更多订单了”底栏。

## 5. 非目标

- 不修改数据库表结构或新增 Alembic 迁移。
- 不修改既有 `GET /api/v1/orders`、`GET /api/v1/orders/{order_id}` 及 Admin 接口契约。
- 不执行未授权的 pytest、Vitest、小程序编译及真机动态验收。

## 7. 方案设计

1. **后端无冲突接口扩展**：
   - 在 `trade_query_schemas.py` 新增 `ConsumerOrderSummaryRead`（`pending_payment: int`、`awaiting_delivery: int`）。
   - 在 `ConsumerTradeQueryService` 新增 `order_summary(user_id)`，使用单条 SQL 条件聚合按 `Order` + `Fulfillment` 口径统计本人待付款和待核销全量笔数。
   - 在 `transaction_router.py` 的 `/orders/{order_id}` 之前注册 `GET /api/v1/orders/summary`，沿用 `UserPrincipal` 与统一 `ResponseModel`。
2. **契约同步**：运行 `export_openapi.py` 导出根 `openapi.json`，运行 `pnpm generate-api` 生成 `@pinjie/api-client`。
3. **小程序订单列表重构**：
   - 顶部 5 个胶囊筛选（`全部`、`待付款`、`待核销`、`已完成`、`已取消`），接入 `/orders/summary` 展示待付款和待核销右上角金柑橙全量角标（> 99 显示 `99+`，0 不展示）。
   - 列表改为 `useInfiniteQuery` 配合 `useReachBottom` 触底连续加载与下拉刷新，加载完毕显示“没有更多订单了”分割线。
   - 每张订单卡片复用 `order.merchant_snapshot`（零 N+1 请求）呈现商家 LOGO（`aspectFit`）、商家名、点击进商家详情、状态语义标签、商品列表行、待付款每秒倒计时条（到 0 提示已超时，不自动取消）、待核销一单一码提示条、时间与 `已抵 X 积分` 暖色标签、件数及实付/应付金额（已取消态使用灰蓝文字）。
   - 操作按钮：待付款提供“取消订单”（二次确认 + 取消接口 + 刷新列表与角标）与“微信付款”（进入待付款详情页）；待核销提供“导航”（存在坐标时调用 `Taro.openLocation`）与“查看核销码”（进入订单详情查看核销码）；已完成/已取消提供“再来一单”（直接调用 `startCheckout` 进入结算，异常弹窗提示）。
