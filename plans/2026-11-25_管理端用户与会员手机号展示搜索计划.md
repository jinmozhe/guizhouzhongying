# 管理端用户与会员手机号展示搜索计划

## 1. 当前状态和结果

- 当前状态：已结束
- 结束结果：已完成；后端接口、OpenAPI 契约、API Client 与管理端用户管理、会员档案及推荐关系页面已同步，适用轻量门禁与文档治理检查通过，重型验证按策略未执行

## 2. 关联需求

- `BASE-BE-003`：提供用户管理基础能力，认证、授权和审计在服务端生效。
- `BASE-ADMIN-002`：管理页面覆盖加载、空数据、失败、无权限和成功反馈。
- `BASE-ADMIN-003`：运营能力与服务端权限一致，只使用生成契约。
- `BASE-ADMIN-006`：提供会员分销财务查询能力，不提供关系重绑或伪造数据。
- `BASE-API-001` 与 `BASE-API-002`：根 `openapi.json` 为唯一契约，`packages/api-client/src/` 由契约自动生成。

## 3. 背景

当前 C 端用户经微信一键授权验证的手机号保存在 `users.phone_e164`（配套 `phone_verified_at` 与 `phone_verification_source`），但管理端用户列表、用户详情及会员档案列表接口均未返回手机号，也不支持按手机号搜索。运营人员在后台核对用户与会员信息时无法直接看到或定位手机号。

## 4. 目标

1. 后端管理端用户列表、用户详情及用户修改返回体补充已验证手机号字段（`phone_e164`、`phone_bound`、`phone_verified_at`），用户列表支持按手机号模糊搜索。
2. 后端管理端会员列表及选中导出接口通过只读查询模型关联 `users` 表，补充会员已验证手机号及相关标识字段，支持按手机号模糊筛选。
3. 导出最新 `openapi.json` 并重新生成 `packages/api-client/src/`。
4. 管理端用户管理页、会员档案页及复用会员列表的推荐关系网络页展示格式化后的完整手机号（中国大陆号码去掉 `+86` 前缀，未绑定显示“未绑定”标签），支持一键复制和按手机号搜索。

## 5. 非目标

1. 不在管理端提供手工新增或修改用户手机号的表单，避免破坏 `ck_users_verified_phone` 可信微信验证约束及商家/物业自动绑定逻辑。
2. 不修改数据库表结构，不新增 Alembic 迁移。
3. 不修改 C 端小程序接口响应模型 `MemberProfileRead` 或 `ConsumerUserRead`。
4. 不执行未获授权的 pytest、Vitest、Admin production build、Playwright、浏览器自动化、Git 提交或推送。

## 6. 现状分析

1. `apps/backend/app/db/models/identity.py`：`User` 模型已有 `phone_e164`、`phone_verified_at`、`phone_verification_source` 列以及 `phone_bound` 属性。
2. `apps/backend/app/domains/admin/schemas.py`：`AdminUserRead` 未包含手机号字段；`apps/backend/app/domains/auth/schemas.py` 的 `UserPrincipalOut` 同样未包含。
3. `apps/backend/app/db/repositories/identity.py`：`UserRepository.list_users` 的搜索过滤仅匹配 `username`、`display_name` 和 `email`。
4. `apps/backend/app/services/commerce_reporting.py`：`CommerceReportingService` 的 `members` 资源直接查询单表 `MemberProfile` 并输出 `MemberProfileRead`，未联查 `users` 表，也不支持手机号筛选。
5. `apps/admin/src/features/users/UsersPage.tsx`、`MembersPage.tsx` 和 `ReferralNetworkPage.tsx` 均未展示手机号列与手机号筛选。

### 7.2 详细改动

1. **后端用户查询与响应**：
   - `AdminUserRead` 与 `UserPrincipalOut` 增加 `phone_e164: str | None = None`、`phone_bound: bool = False`、`phone_verified_at: datetime | None = None`。
   - `AdminManagementService._user_read` 透传上述字段。
   - `UserRepository.list_users` 的 `search` 过滤新增 `User.phone_e164.ilike(pattern)`，先对入参去首尾空格。
2. **后端会员只读聚合与筛选导出**：
   - `commerce_reporting.py` 新增 `AdminMemberProfileRead(MemberProfileRead)`，扩展 `username`、`display_name`、`phone_e164`、`phone_bound`、`phone_verified_at`。
   - `CommerceFilters` 新增可选字段 `phone: str | None`（允许 `members` 资源使用，其他资源沿用白名单校验返回 422）。
   - `CommerceReportingService.page` 与 `export` 对 `members` 走 `MemberProfile` 左连接 `User` 的只读查询，继续按 `MemberProfile.id.desc()` 分页排序，导出结果包含新增白名单字段。
   - `commerce_reporting_router.py` 的 `/admin/members` 返回类型切换为 `PageResult[AdminMemberProfileRead]`。
3. **管理端适配**：
   - 新增公共工具 `apps/admin/src/lib/phone.ts`，提供 `formatPhoneForDisplay`（去除中国大陆 `+86` 前缀，空值返回 `null`），并供各页面复用。
   - `UsersPage.tsx` 新增“手机号”列（支持复制与验证时间提示，未绑定显示标签），搜索框提示更新为“用户名、显示名称、手机号或邮箱”。
   - `CommerceList.tsx` 支持筛选字段自定义 `placeholder` 与输入首尾去空格；`commerce.ts` 更新 `members` 返回类型。
   - `MembersPage.tsx` 与 `ReferralNetworkPage.tsx` 均接入 `AdminMemberProfileRead`，增加“手机号”筛选与“手机号”展示列。
   - 同步更新 `apps/admin/src/test/server.ts` 与 `StageC.test.tsx` 中的用户 mock 字段。

## 11. 风险与回滚

- 风险 1：管理端明文展示用户手机号属于个人敏感信息展示；已由现有 `users:read`、`members:read`、`members:export` 服务端权限保护，且 `/api/v1/admin/members` 已在 `payload_sanitizer.py` 敏感路由列表中，不记录请求体。
- 风险 2：`User.phone_e164.ilike` 模糊搜索在大数据量下无法命中 B-Tree 唯一索引；当前阶段满足运营尾号搜索诉求，后续数据增长可按需增加精确号码分支或 `pg_trgm` 索引。
- 回滚方式：不涉及数据库迁移，直接回退本任务改动的文件并重新导出 `openapi.json` 与客户端即可完整恢复。
