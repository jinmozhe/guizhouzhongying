# 微信小程序标准配色方案

## 1. 定版依据与适用范围

本标准依据用户确认的 `output/Palette2.dc.html` 定版，覆盖微信小程序全部页面、分包、公共组件、弹层和状态，包括登录、个人资料、商家、物业、积分、交易及账户页面。颜色值、语义与搭配以本文为唯一来源；尺寸、组件行为和页面结构继续遵循 [UI 与交互规范](../../architecture/miniapp-ui-standard.md)。

统一方向：深钴蓝承担品牌和主操作，金柑橙强调积分权益，天青蓝少量点缀，浅色背景承载内容，价格单独使用价格红。品牌色不按页面、角色或业务模块更换。

现有全部 32 个小程序路由已通过共享主题及适用的页面样式接入本标准；原生配置、TabBar 图片、账户背景、登录插画和分享封面已同步。实施与验证记录见[全端配色迁移计划](../../../plans/2026-11-23_小程序全端标准配色迁移计划.md)。历史设计图保留旧配色用于布局参考；微信编译、真机视觉和动态交互验收未执行。后续新建和修改界面必须按本文实施并核对第 8 节的实现入口。

原始色板保留为设计依据，其“送货上门”“积分兑换”等示例不构成产品需求。当前业务示例使用到店消费、整单核销、SKU 积分抵扣，能力边界以 [产品需求基线](../../PROJECT_REQUIREMENTS.md)为准。

## 2. 基础色板

以下 12 色保持用户确认值，不另增品牌色。

| 类别 | 名称 | 色值 | 标准用途 | 使用限制 |
| --- | --- | --- | --- | --- |
| 品牌 | 深钴蓝 | `#253E77` | 主按钮、选中态、标题强调、品牌图标 | 不用于价格，不铺满普通列表 |
| 品牌 | 深湾蓝 | `#255878` | Banner 渐变深端、深色品牌内容面 | 不替代全局主操作色 |
| 点缀 | 天青蓝 | `#15A0E0` | 装饰图标、光晕、小面积亮点 | 不用于浅底小字或唯一操作标识，不配白色小字 |
| 权益 | 金柑橙 | `#E8A150` | 积分卡、积分权益及适用的权益按钮 | 配墨蓝字；支付和结算仍用深钴蓝 |
| 金额 | 价格红 | `#CC3A1E` | 售价、应付现金、优惠金额 | 仅用于价格与优惠金额，不用于错误、删除或通知角标 |
| 状态 | 成功绿 | `#1F7A5A` | 营业中、已完成、已核销等明确事实 | 未确认的支付、退款和核销不得显示成功绿 |
| 辅助 | 麦穗黄 | `#D4A921` | 积分卡渐变、金币装饰 | 不单独承担警告文字或成功状态 |
| 信息 | 天青深 | `#0B6CA6` | 文字链接、拨号导航操作、信息标签 | 浅底正文链接使用此色 |
| 背景 | 页面底 | `#F4F7F9` | 整页背景、骨架及中性占位 | 重要内容使用白色面分层 |
| 背景 | 晴霜蓝 | `#E3F0F2` | 搜索输入区、商家区底、选中项底 | 不作为成功或积分专属底色 |
| 文字 | 墨蓝 | `#16233F` | 标题、正文、积分卡数字、橙底按钮字 | 深色品牌面改用白字 |
| 文字 | 次要文字 | `#56627A` | 地址、说明、时间、占位提示、划线参考价 | 必须阅读的文字不再降低透明度 |

原稿中的白色及四个有色配套值作为固定辅助色保留，不能自行扩展为另一套主题。

| 名称 | 色值 | 标准用途 |
| --- | --- | --- |
| 白色 | `#FFFFFF` | 卡片、表单、弹层、导航底及深色面文字 |
| 分隔色 | `#DDE6EA` | 装饰性分隔线、卡片边框 |
| 积分浅底 | `#FDF1E1` | 积分标签、警告及错误提示底 |
| 积分深字 | `#8A4B00` | 积分标签文字、警告和错误提示文字 |
| 成功浅底 | `#E6F0ED` | 成功标签背景 |

白色加四个有色辅助值均来自原稿。分隔色只作弱分隔；必须靠边框识别的输入框、复选框和操作控件使用次要文字色或品牌色边框。

## 3. 语义 tokens

下面的名称是设计与代码映射的统一语义，色值引用第 2 节。实现可沿用现有 Sass 变量名称，但同一语义只能有一个来源，不在页面复制色值。

| token | 对应色或组合 | 适用对象 |
| --- | --- | --- |
| `color-primary` | 深钴蓝 | 主要操作、已选规格、开关及复选框选中态 |
| `color-primary-pressed` | 墨蓝 | 主按钮按下态 |
| `color-primary-soft` | 晴霜蓝 | 选中项及品牌轻提示背景 |
| `color-brand-deep` | 深湾蓝 | 品牌深色面和品牌渐变 |
| `color-accent` | 天青蓝 | 非必要装饰 |
| `color-reward` / `color-reward-end` | 金柑橙 / 麦穗黄 | 积分权益及积分卡渐变 |
| `color-reward-soft` / `color-reward-ink` | 积分浅底 / 积分深字 | 积分抵扣标签 |
| `color-price` | 价格红 | 现金价格及优惠金额，独立于主操作 |
| `color-background` / `color-surface` | 页面底 / 白色 | 页面与内容面 |
| `color-surface-tint` | 晴霜蓝 | 商家区及搜索底 |
| `color-text` / `color-text-secondary` | 墨蓝 / 次要文字 | 正文与次要信息 |
| `color-on-brand` / `color-on-reward` | 白色 / 墨蓝 | 深色品牌面与积分面文字 |
| `color-border` / `color-control-border` | 分隔色 / 次要文字 | 弱分隔与必要控件轮廓 |
| `color-disabled-bg` / `color-text-disabled` | 页面底 / 次要文字 | 禁用态，配合禁用行为与原因 |
| `color-success` / `color-success-soft` | 成功绿 / 成功浅底 | 已确认成功状态 |
| `color-info` / `color-info-soft` | 天青深 / 晴霜蓝 | 信息链接及说明标签 |
| `color-warning` / `color-warning-soft` | 积分深字 / 积分浅底 | 待确认、未知结果和风险提示 |
| `color-danger` / `color-danger-soft` | 积分深字 / 积分浅底 | 错误、删除、撤销和不可逆风险 |

警告与错误复用现有暖色辅助值，通过明确标题、错误或警告图标、操作文案区分；错误提示固定为“失败原因 + 可执行动作”，危险确认写明对象与后果，不能呈现为积分奖励。积分深字不会替代主按钮。`color-danger` 与 `color-price` 保持独立，禁止为了制造红色错误而复用价格 token。

遮罩固定使用墨蓝 44% 不透明度，白色弹层承载正文。按下反馈只允许使用表内色值或墨蓝 8% 叠层；不能通过降低整个控件透明度造成标签不可读。必要阴影仅使用墨蓝低透明度，不引入彩色阴影。

## 4. 组件搭配

| 组件 | 默认搭配 | 选中、按下及其他状态 |
| --- | --- | --- |
| 页面、卡片、弹层 | 页面底 + 白色内容面 + 墨蓝正文 | 地址、说明和时间使用次要文字 |
| 主按钮 | 深钴蓝底 + 白字 | 按下为墨蓝；加载保留原标签与加载反馈，禁止重复提交 |
| 次按钮 | 白底 + 天青深字和边框 | 按下用晴霜蓝底；有多个次操作时保持一致 |
| 积分权益按钮 | 金柑橙底 + 墨蓝字 | 按下叠加墨蓝 8%；仅在实际支持的积分操作中使用 |
| 危险操作 | 白底 + 积分深字和边框 | 确认区用积分浅底，明确“删除”“撤销”等文案与后果 |
| 禁用按钮 | 页面底 + 次要文字 + 分隔色边框 | 真实禁用并展示适用原因；不能只换颜色 |
| 搜索栏 | 白色页面区内用晴霜蓝输入底，墨蓝输入字、次要占位字 | 页面底或晴霜蓝区内可使用原稿白色搜索面；右侧搜索按钮始终深钴蓝配白字 |
| 输入框 | 白底或页面底 + 墨蓝输入字 + 次要文字标签 | 聚焦深钴蓝边框；错误用积分深字边框和就近原因 |
| 分类、筛选、SKU | 白底 + 次要文字 | 选中用晴霜蓝底 + 深钴蓝字与边框，并保留勾选或位置标记 |
| TabBar | 白底 + 次要文字和图标 | 选中深钴蓝；PNG 图标与文字同步，不能保留红色选中图 |
| 顶部导航 | 白底 + 墨蓝标题和返回图标 | 深色品牌头部用白字，背景和系统文字样式同步；系统胶囊由微信控制 |
| 商家区 | 首页品牌商家采用页面底 + 独立白卡，分类页采用晴霜蓝区底 + 白色 LOGO 容器 | 首页缺图占位采用深钴蓝底和白字。分类页选中采用深钴蓝边框及文字。商家真实 LOGO 保留 |
| 积分标签 | 积分浅底 + 积分深字 | 示例“最多可抵 50 积分”，内容必须来自真实 SKU 规则 |
| 成功标签 | 成功浅底 + 成功绿 | “营业中”“已核销”“退款完成”等必须有事实支持 |
| 信息标签 | 晴霜蓝 + 天青深 | “到店核销”等信息文案；多规格标签用晴霜蓝 + 深钴蓝 |
| 价格 | 白底 + 价格红，货币符号与金额同色 | 划线参考价用次要文字；积分数量用积分深字或墨蓝 |
| 应用自绘数量角标 | 深钴蓝底 + 白字 | 商品详情底栏购物车角标用金柑橙底和墨蓝字；微信原生 TabBar 购物车角标的外观由平台控制 |
| 加载、空态、断网 | 页面底或白底 + 次要文字，骨架用晴霜蓝 | 失败给出原因与重试；空态不增加暖红插画底 |
| 钱包和积分流水 | 金额默认墨蓝，状态按语义色 | 收入、支出、冻结和追回用文字与正负号区分，不机械套用红涨绿跌 |

## 5. Banner 与积分卡

只在现有 Banner、品牌头部和积分资产卡使用以下渐变；普通商品卡、表单、列表和底部操作栏使用纯色。配色标准不要求新增 Banner 或权益入口。

```css
/* 品牌 Banner：正文位于左侧深色区域，右下光晕不经过正文。 */
background:
  radial-gradient(
    ellipse at 85% 130%,
    rgba(21, 160, 224, 0.75),
    rgba(21, 160, 224, 0) 60%
  ),
  linear-gradient(120deg, #253E77, #255878);
color: #FFFFFF;

/* 积分卡：标题、数值和说明全部使用墨蓝。 */
background: linear-gradient(120deg, #E8A150, #D4A921);
color: #16233F;
```

Banner 在窄屏和长标题下仍须保证文字落在深色区域。无法避开光晕时，移除文字区域的光晕或增加不透明深钴蓝文字承载面，禁止白字直接覆盖天青亮部。积分卡不得使用白色小字、白色金额或淡色说明。

页面的大部分面积由页面底、白色和晴霜蓝构成；深钴蓝集中于主操作和品牌区域；橙黄集中于积分；天青只作少量装饰；价格红只出现在金额。普通内容区同一操作组只设一个主要动作。

## 6. 全页面覆盖

| 页面组 | 统一要求 |
| --- | --- |
| 首页、分类、商家列表及详情 | 搜索、筛选、商家区和商品卡采用第 4 节组合，商家角色不单独换主题 |
| 商品详情、SKU、购物车、结算 | 主操作深钴蓝，现金价格红，积分标签暖色；选中和价格分别消费独立 token |
| 订单、支付、核销、售后 | 交易状态按后端事实着色；待支付和待核销使用信息色，处理中及未知使用警告色，确认成功才用绿色 |
| 登录、我的、个人资料 | 主操作统一深钴蓝；原红色品牌背景迁移为蓝色品牌头部与浅色内容面，原布局、插画形状和安全区保留 |
| 会员、积分、推荐、钱包 | 积分权益使用橙黄；账户余额和普通流水保持墨蓝，页面不各设紫色、粉色等独立主题 |
| 商家工作台、物业发分、对账 | 与消费者端共享主操作和状态色，不因身份增加另一套配色 |
| 设置、会话、隐私、帮助、地址 | 白色内容面、墨蓝正文、天青深链接；撤销和删除使用统一危险提示 |
| 所有弹层及页面状态 | 覆盖正常、按下、选中、禁用、加载、空态、失败、未登录、结果未知，不能只迁移正常截图 |

商品图片、商家 LOGO、用户头像及真实业务图片不强制滤色。可控品牌插画和账户背景须与本标准一致。微信原生授权、支付、相机、系统导航文字和 TabBar 数量角标等不提供任意颜色参数的外观由平台决定，禁止伪造系统界面追求统一。本地锁定 Taro 的 `setTabBarBadge.Option` 仅提供 index、text 和回调，无角标颜色参数；因此保持现有原生角标及数量行为。原生弹窗已提供的 confirmColor、cancelColor 则统一映射品牌或危险语义。

## 7. 可读性与验收

沿用 UI 规范的普通文字对比度至少 4.5:1 目标。以下为不透明纯色按 sRGB 相对亮度计算的对比值，保留两位小数；数值不代表渐变、图片、透明叠层或真机已验收。

| 前景 / 背景 | 对比度 | 结论 |
| --- | --- | --- |
| 白色 / 深钴蓝 | 10.32:1 | 可用于主按钮小字 |
| 白色 / 深湾蓝 | 7.65:1 | 可用于品牌深色面 |
| 墨蓝 / 金柑橙 | 7.16:1 | 可用于积分按钮与卡片 |
| 墨蓝 / 麦穗黄 | 7.05:1 | 可用于积分渐变末端 |
| 次要文字 / 晴霜蓝 | 5.26:1 | 可用于说明与搜索占位 |
| 天青深 / 晴霜蓝 | 4.86:1 | 可用于信息标签 |
| 价格红 / 白色 | 5.01:1 | 可用于价格及货币符号 |
| 成功绿 / 成功浅底 | 4.52:1 | 可用于成功标签，禁止再淡化前景 |
| 积分深字 / 积分浅底 | 6.10:1 | 可用于积分及风险提示 |
| 白色 / 天青蓝 | 2.94:1 | 不用于文字组合 |
| 白色 / 金柑橙 | 2.18:1 | 不用于文字组合 |

颜色不能独立表达状态。选中项有边框、勾选或位置标记；错误与成功有文字；禁用有行为约束。浅色分隔线不能充当唯一控件识别边界。以实际背景重新核对渐变上文字、富文本、透明遮罩及图片上的标签，不以纯色色板计算代替。

## 8. 代码落点与完成判定

| 实现入口 | 迁移要求 |
| --- | --- |
| `apps/miniapp/src/styles/palette.json` | 色值的唯一机器来源；原生配置、控件与图片生成脚本直接读取，`_palette.scss` 由脚本生成，禁止手改 |
| `apps/miniapp/src/styles/tokens.scss` 与 `colors.ts` | Sass 与原生参数映射同一语义；`auth-*`、`profile-*`、`account-*` 和积分变量不另设主题 |
| `apps/miniapp/src/styles/app.scss` | NutUI 主题消费统一 tokens；`.price`、`.price-small` 与按钮主色拆分 |
| 页面、Feature 与公共组件样式 | 清查散落的 HEX、RGB、命名色和内联颜色，按实际用途映射，禁止全局机械替换红色 |
| `apps/miniapp/src/tab-bar.json` 与同源 PNG 生成器 | 清单管理页面和图形，原生配置与生成器从 `palette.json` 读取普通态和选中态颜色；重新生成并核对图标，不得只改配置 |
| 账户背景、登录插画和相关生成器 | 保留构图、尺寸与几何规则，统一可控品牌配色；生成源与产物一起更新 |
| 原生页面配置 | 核对导航、窗口背景、加载背景与 TabBar，防止切页露出旧主题 |
| `docs/design/miniapp/` 设计图集 | 历史图片保留；后续新图遵守本文，旧图颜色不再作为实现依据 |

只有共享 tokens、价格独立语义、页面覆盖、原生配置和品牌资产全部迁移，且适用轻量门禁通过，才能报告“源码配色统一完成”。微信开发者工具和真机的正常及异常状态视觉验收独立记录；未执行时明确标注。标准文档定版、源码迁移完成、视觉验收完成分别交付，不能相互替代。
